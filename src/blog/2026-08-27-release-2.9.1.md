We just released three patch versions of AiiDA, v2.9.1, v2.8.2 and v2.7.5, so that the same fixes are available on the 2.7, 2.8 and 2.9 series.

Two of the fixes are worth calling out.
`verdi process dump` silently omitted repository files from output data types that had no `SinglefileData` or `FolderData` sibling, and now writes the files of all repository-backed outputs ([#7525](https://github.com/aiidateam/aiida-core/pull/7525)).
A failed `COPY` stash deleted the sibling stashes that happened to share the same UUID shard, which could remove unrelated stashed data ([#7563](https://github.com/aiidateam/aiida-core/pull/7563)).
If you use stashing, we recommend upgrading.

On the 2.8 and 2.9 series, stash failures are now also recorded in the process report ([#7572](https://github.com/aiidateam/aiida-core/pull/7572)) instead of failing silently, and v2.9.1 additionally stops `verdi` commands from emitting spurious errors while releasing unclosed broker and storage backend resources on shutdown ([#7551](https://github.com/aiidateam/aiida-core/pull/7551)).

You can find the full list of changes in the CHANGELOG for [v2.9.1](https://github.com/aiidateam/aiida-core/blob/v2.9.1/CHANGELOG.md#v291---2026-08-27), [v2.8.2](https://github.com/aiidateam/aiida-core/blob/v2.8.2/CHANGELOG.md#v282---2026-08-27) and [v2.7.5](https://github.com/aiidateam/aiida-core/blob/v2.7.5/CHANGELOG.md#v275---2026-08-27).

Happy computing!
